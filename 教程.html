dir2chat 26.10.17

目录 → 聊天 推送服务

监听一个目录，把新增或变更的图片和 Markdown 定时推送到企业微信、QQ 的聊天里。带 Web 配置界面，Docker 一键起。每条规则可独立定时与独立轮询间隔、通道可自定义名称、记录页固定 15 行分页（可筛选/导出/点空白翻页）、配置可备份导入、内置时区与时间同步（支持自定义服务器）、手机端适配。

1这是什么

dir2chat 是一个常驻的 Docker 服务：

📁 你的目录→ ⏱ 定时轮询扫描→ 🔁 幂等去重→ 💬 企业微信 / QQ

定时轮询（默认 60s，可在界面上调，规则可单独设间隔）发现新文件或内容变更时，按你配置的规则推送。图片超大会自动压缩、Markdown 超长会退化成文件消息、再超长会切片。最典型的用法：把每天生成的报表截图 + Markdown 报告自动发到群里。

支持的通道与能力对比

通道文本Markdown图片文件可发给备注
群机器人 Webhook✓✓≤2MB5B–20MB内部群最简单；file 无文件名；20条/分
智能机器人经MD≤20KB≤10MB≤20MB内部群能力最强；群聊 chat_type=2

微信个人号没有官方对外发送通道，本项目不包含（需另行在 Windows 常驻机跑 RPA / WeChatFerry）。

2环境要求

  • Docker Engine 20.10+，且包含 docker compose v2（docker compose version 有输出）
  • 支持 Linux amd64 / arm64：官方镜像为双架构，docker pull 会自动匹配本机架构
  • 需要能访问 Docker Hub 拉取镜像；完全离线的机器可从源码自行构建（见「从源码构建」一节）
  • 约 250MB 磁盘空间
  • 仅本机 / 内网访问：防火墙放行 8899 端口，不要直接暴露公网

3安装

镜像发布在 Docker Hub：smi1ezz/dir2chat，支持 amd64 / arm64 双架构，latest 始终指向最新版。

方式一：一键脚本（推荐）

git clone https://github.com/Smi13zZ/dir2chat.git
cd dir2chat

# 安装（检查 Docker → 拉取镜像 → 生成配置 → 启动）
sudo bash install.sh
请务必加 sudo（用 root 权限运行）。安装脚本要调用 Docker——访问 /var/run/docker.sock、拉取镜像、启动容器——普通用户执行会报 permission denied while trying to connect to the Docker daemon socket。
如果你已经把自己加进了 docker 组（sudo usermod -aG docker $USER，之后重新登录或执行 newgrp docker），那么可以不加 sudo，直接 bash install.sh。

脚本会自动完成：检查 Docker → 生成 .env → 校验监听目录 → 创建 config/ → 拉取镜像 → 启动容器 → 等待健康检查。

方式二：手动 docker compose

把仓库里的 docker-compose.yml 与 .env.example 放到同一目录，.env.example 改名为 .env 并填好 WATCH_DIR：

sudo docker compose pull      # 拉取镜像（首次约 250MB）
sudo docker compose up -d     # 启动

可用的前置变量

把变量写在 bash install.sh 之前，即可免手工改 .env：

bash install.sh                             # 就地安装（默认：装到脚本所在目录）
DIR2CHAT_PORT=8091 bash install.sh          # 换对外端口（8899 被占用时）
WATCH_DIR=/你真实的目录 bash install.sh   # 指定监听目录
FORCE=1 bash install.sh                     # 目录已部署过：覆盖程序文件、保留 config/ 与 .env
bash install.sh /opt/dir2chat               # 指定安装目录（只拷运行所需文件）

# 可以叠加：一次把端口和监听目录都定好
sudo DIR2CHAT_PORT=8091 WATCH_DIR=/你真实的目录 bash install.sh

这些值都会被写回 .env（一行一条），后续 docker compose 命令会自动沿用。

Windows 用户：在 WSL2 或 Git Bash 里跑 sudo bash install.sh；或 Docker Desktop 装好后直接手动 docker compose up -d。

4配置监听目录（必须）

两种方式，任选其一。

方式一（推荐）：安装时直接带变量，脚本会自动写进 .env：

sudo WATCH_DIR=/你真实的目录 bash install.sh

方式二：装完之后手动改 .env：

WATCH_DIR=/你真实的目录
DIR2CHAT_PORT=8899
改 .env 前先确认有 root 权限。如果你是用 sudo bash install.sh 装的，那么 .env、config/ 都归 root 所有，普通用户打开会提示「只读 / 无法保存」。请用 sudo nano .env（或 sudo vi .env）编辑，改完再 sudo docker compose up -d。
⚠ 一行一条，千万不要两行写在同一行。常见错误是这样粘在一起：
WATCH_DIR=/你真实的目录DIR2CHAT_PORT=8899
这会让 WATCH_DIR 变成一个不存在的路径、同时 DIR2CHAT_PORT 也彻底失效。
WATCH_DIR=... 之后必须换行。安装脚本写 .env 时会自动保证「一行一条」（不会追加到上一行末尾）。

这个目录会被只读挂进容器的 /data。dir2chat 会递归扫描其下的子目录——所以像 share/2026-10-11/ 这样的日期子目录也能自动识别。

改完让配置生效：sudo docker compose up -d。注意：.env 里写的是宿主机路径，容器内部固定是 /data。

6定时开关（每条规则独立控制）

定时开关位于每条规则内部，各规则互不影响。打开某条规则的 ⏰ 定时开关：

  • 开启后，只有在该规则的时间窗口内才会扫描并推送这条规则；窗口外自动暂停（文件不会丢，回到窗口后继续推送）。
  • 不同规则可设不同时段：如「行情图」只在 09:00–15:00 推送，「日报」全天推送。
  • 手动「立即扫描」不受定时限制——任何时候都能强制触发一次推送。
  • 支持多条时间窗口，也支持跨午夜：
09:00 – 22:00
白天工作时段推送
22:00 – 06:00
深夜静默（跨午夜）
  • 时区默认 Asia/Shanghai（依赖 tzdata；无时区数据时回退服务器本地时间）。
  • 规则卡片实时显示相位：「✅ 当前在推送窗口内」或「⏸ 窗口外暂停」。
  • 配置保存在 config/config.json 的 rules[].schedule，重新部署时会被保留。
典型用法：给「行情图」规则设 09:00–15:00，只在交易时段自动推送；其余规则保持全天。

7轮询间隔可调（全局 + 规则级）

  • 全局：「概览 → 扫描设置」里可改轮询间隔（秒，最小 5）、文件稳定时间、每轮最多文件数、扫描总开关，点「保存扫描设置」生效。
  • 规则级：每条规则的「独立轮询间隔」填 0 或留空 = 跟随全局；填 ≥5 的整数则该规则单独按此间隔扫描。
  • 不同规则可有不同节奏，互不干扰。
推荐：全局 60s 够用；某条要更及时就单独设 15s，不必整体加快。

8绑定通道只显示已启用的通道

  • 规则卡片的通道绑定列表默认只列出已启用的通道，未启用的不再出现，避免误绑。
  • 若某个已绑定的通道随后被停用，它仍会保留显示（虚线灰显 + 「已停用」标签），方便手动解绑，不会「看不见又解不掉」。
  • 其余未绑定的停用通道会隐藏，并提示隐藏了几个。
补充：切换标签时内容区会自动回到顶部，顶部标签栏始终固定在原位，不会上下滑动。

9记录页（筛选 / 分页 / 导出）

  • 两个并列按钮：「发送记录」与「事件日志」，点哪个显示哪个。
  • 表格宽度固定，内容超长自动省略号截断，鼠标悬停显示完整内容。
  • 筛选：时间（模糊）、通道、类型、级别；发送记录另有「只看失败/跳过」。
  • 分页：每页固定 15 行，超出只翻页、纵向不滚动；不足 15 行补空行，每页高度恒定不跳动。
  • 空白处也能翻页：表格下方的留白点一下即翻到下一页（到末页后再点翻上一页）；点到表格/按钮本身不会误触发。
  • ⬇ 导出：当前筛选结果导出为 CSV（带 BOM，Excel 打开中文不乱码）。

10界面宽度与项目图标

  • 顶栏、标签栏、内容区三者等宽且居中：共用同一个宽度变量（默认最大 1543px， = 参考站 msn.cn 的 1187px × 1.3），左右留白自动均分。
  • 滚动条始终在窗口最右侧：滚动容器是通栏的外层，内容收窄居中在其内部，不受内容宽度影响。
  • 翻页仍是全屏空白点击翻页：点内容两侧的留白、甚至滚动条旁的区域都能翻页。
  • 窗口宽度 ≤ 1600px 时自动取消宽度上限，避免窄屏被明显压缩。
  • 项目 logo 与网页图标：左上角显示项目 logo（纯图标，26px）， 浏览器标签页 / 添加到主屏也都有对应图标（favicon 16/32、apple-touch-icon 180）。

11时区与时间（自动同步 / 手动设置）

「概览」页新增时区与时间区块，界面上有实时时钟与时区徽标：

  • 时区：内置常用时区（默认 Asia/Shanghai，即 UTC+08:00 北京/重庆/中国香港）， 也可从 zoneinfo 里选其它地区；切换后定时窗口判断与记录时间一并跟随。
  • 自动同步（默认）：选择时间服务器后点「立即同步」，或让后台按 time.auto_sync_hours（默认 6 小时）周期自动对时。 点「测试服务器」只查询不改时间，会显示本机与服务器的偏差和网络延迟。
  • 自定义服务器：在「自定义服务器」区填入地址点「添加」即可加入下拉并可选中。 支持域名 / IPv4 / IPv6 / 局域网主机名，可带端口，例如 192.168.1.1、ntp.local、192.168.1.5:123； 误粘贴的 ntp://、http:// 前缀会被自动剥掉。 已添加项以标签展示，点标签上的 × 可删除。
  • 手动设置：切到「手动设置」，选好日期时间后点「应用时间」（可先点「填入当前时间」）。
  • 校时需要权限：容器默认不能改系统时间，已在 docker-compose.yml 里加上 cap_add: [SYS_TIME]。若缺失，界面会明确提示原因与改法，不会静默失败。
时间同步用内置的轻量 SNTP 客户端（UDP 123 标准报文），不依赖 ntpd / chrony / systemd-timesyncd，容器里直接可用。

13配置备份 / 导入

「概览」页顶部新增配置备份：

14推送规则与行为

  • 轮询扫描：默认 60s 一次（概览页可调，规则可单独覆盖）；文件需「稳定 5s 且大小两次不变」才处理，避免发半截文件
  • 幂等：同一 (规则, 通道, 路径, sha256) 只发一次；内容变了才重发（每天重写过的报告会重发，没动的不刷屏）
  • 图片压缩：超过通道上限自动压（webhook 2MB / 智能机器人 10MB）
  • Markdown 退化：超 3800 字节变文件消息；再超长切片并带 (i/n) 标记
企业微信 webhook 的 file 消息无文件名（官方限制）。若要在聊天里看出是哪份报告，可调低 Markdown 上限多发图片，或直接用智能机器人通道（文件带文件名）。

15日常管理

下面的命令默认都加了 sudo。如果你已经把当前用户加进 docker 组，可以把 sudo 去掉。
# 状态
curl http://<IP>:8899/api/status

# 备份配置（导出 JSON）
curl -OJ http://<IP>:8899/api/config/export

# 停止 / 重启 / 日志
sudo docker compose down
sudo docker compose restart
sudo docker compose logs -f

# 升级到最新镜像
sudo docker compose pull && sudo docker compose up -d

# 改配置（sudo 装的 .env 归 root 所有，必须加 sudo 才能保存）
sudo nano .env

# 卸载
sudo docker compose down && rm -rf config .env

16故障排查

现象处理
端口被占用改 docker-compose.yml 的 8899:8899 左边端口，如 9090:8899
目标架构与镜像不符官方镜像已支持 amd64 / arm64；其它架构可用 docker compose build 从源码构建
扫描不到文件检查 WATCH_DIR 是否存在、容器是否挂上 /data、规则 include 通配
规则绑定看不到新通道点规则页右上角「↻ 刷新通道」
通道「测试」失败看返回错误码说明（界面解释常见 errcode，如 45009 限频、93000 参数错）
镜像拉取慢 / 超时给 Docker 配镜像加速器（daemon.json 的 registry-mirrors）后重试 docker compose pull
定时开关不生效确认该规则的定时已启用且窗口非空；用「立即扫描」可随时强制推送验证通道
改了轮询间隔没生效概览页改完要点「保存扫描设置」；规则里设了「独立轮询间隔」会覆盖全局
规则里看不到某个通道该通道未启用。先到「通道」页启用，或点规则页「↻ 刷新通道」
改系统时间报权限错误容器缺 CAP_SYS_TIME。确认 docker-compose.yml 有 cap_add: [SYS_TIME] 后重建容器
自定义时间服务器添加失败检查地址是否含非法字符、端口是否在 1–65535、长度是否超 255；界面会给出具体原因
NTP 同步失败先在「测试服务器」看是否可达；局域网服务器确认 UDP 123 未被防火墙拦截
时间/记录显示时区不对检查「概览」的时区下拉是否选对；切换后记录时间会按新时区显示

17从源码构建 & 清理构建缓存

正常情况下直接用 Docker Hub 上的官方镜像即可，不需要构建。只有这两种情况才需要自己构建：① 你改了源码 / Dockerfile / requirements.txt；② 目标架构特殊、官方镜像跑不了。构建时需要联网拉基础镜像 python:3.11-slim。

# 在仓库目录里构建（打成与 compose 相同的镜像名）+ 重建容器
sudo docker compose build
sudo docker compose up -d --force-recreate
改完源码 / 依赖却不生效？多半是复用了旧的构建缓存。Docker 逐层缓存，requirements.txt 没变时 pip install 那一层会直接复用，导致新代码没进去。清掉缓存再构建：
# 1) 忽略缓存、从头构建（最常用）
sudo docker compose build --no-cache
sudo docker compose up -d --force-recreate

# 2) 清理 BuildKit 构建缓存（-a 连未使用的也清，-f 不交互确认）
sudo docker builder prune            # 交互确认后清理
sudo docker builder prune -af        # 直接全部清掉

# 3) 清理悬空镜像（构建残留的 <none> 旧层）
sudo docker image prune -f

# 4) 先看看各类占用多少，再决定清哪个
sudo docker system df

# 5) 彻底清干净（慎用：会删掉所有未使用的镜像 / 缓存 / 网络）
sudo docker system prune -af
清构建缓存只影响下次构建速度（会重新下载 / 安装依赖），不会动到 config/ 里的数据——通道、规则、发送记录都在 config/ 卷里，安全。
完成！打开 http://<机器IP>:8899 即可在界面里添加通道与规则。凭据由你自己在界面填写，本包不含任何密钥。
