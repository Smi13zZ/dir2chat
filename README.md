# dir2chat 安装与配置教程

[**English**](README_EN.md) ｜ 简体中文

> 版本：**26.10.17** ｜ 一句话：监听一个目录，把新增/变更的**图片和 Markdown** 定时推送到企业微信、QQ 的聊天里，带 Web 配置界面，Docker 一键起。

---

## 1. 这是什么

dir2chat 是一个常驻的 Docker 服务：

- **定时扫描**你指定的目录（默认每 60 秒轮询一次，可在「概览 → 扫描设置」调整，每条规则也可单独设间隔；因为是 Docker 卷 / NFS 场景，刻意不用 inotify）
- 发现**新文件或内容变更**时，按你配置的规则，推送到 **企业微信** 或 **QQ**
- 推送内容自动适配通道能力：图片超大会压缩、Markdown 超长会退化成文件消息、再超长会切片
- 带一个轻量 Web 界面（`:8899`），不需要改代码就能增删通道和规则
- **定时开关**：每条规则独立控制，可只在你配置的时段内自动推送，窗口外自动暂停
- **轮询间隔可调**：全局在「概览 → 扫描设置」调整，规则级可单独覆盖（填 0 跟随全局）

最典型的用法：把每天生成的报表截图 + Markdown 报告，**自动发到群里**。

### 支持的通道与能力对比

| 通道                   | 文本         | Markdown | 图片       | 文件         | 可发给      | 备注                                     |
| -------------------- | ---------- | -------- | -------- | ---------- | -------- | -------------------------------------- |
| 企业微信群机器人 Webhook     | ✓          | ✓        | ✓(≤2MB)  | ✓(5B–20MB) | 内部群      | 最简单，只要一个 URL；file 消息无文件名；20 条/分钟       |
| 企业微信智能机器人（长连接）       | 经 Markdown | ✓(≤20KB) | ✓(≤10MB) | ✓(≤20MB)   | 内部群      | 能力最强；纯文本用 markdown 承载；群聊 `chat_type=2` |
| 企业微信应用消息             | ✓          | ✓        | ✓        | ✓          | **指定成员** | 唯一能发给个人的通道；需 corpid/secret/agentid     |
| QQ 官方机器人（OpenAPI v2） | ✓          | ✓        | ✓        | ✓          | 群 / 私聊   | 需 appId/secret；群主动推送需群主开启开关            |

> 微信**个人号**没有官方对外发送通道，本项目不包含（需要另行在 Windows 常驻机跑 RPA / WeChatFerry）。

## 2. 环境要求

- **Docker Engine 20.10+**，且包含 **docker compose v2**（`docker compose version` 有输出）
- 支持 **Linux amd64 / arm64**：官方镜像为双架构，`docker pull` 会自动匹配本机架构
- 需要能访问 Docker Hub 拉取镜像；完全离线的机器可从源码自行构建（见第 10 节）
- 约 **250MB** 磁盘空间
- 仅本机 / 内网访问：防火墙放行 **8899** 端口（不要直接暴露到公网）

## 3. 安装

镜像发布在 Docker Hub：**`smi1ezz/dir2chat`**（支持 amd64 / arm64；`:latest` 始终指向最新版）。

### 方式一：一键脚本（推荐）

```bash
git clone https://github.com/Smi13zZ/dir2chat.git
cd dir2chat

# 安装（会检查 Docker、拉取镜像、生成配置并启动）
sudo bash install.sh
```

> **⚠ 请务必用 `sudo`（root 权限）运行。** 脚本要访问 `/var/run/docker.sock`、拉取镜像、启动容器，普通用户会报
> `permission denied while trying to connect to the Docker daemon socket`。
> 如果已把当前用户加入 `docker` 组（`sudo usermod -aG docker $USER` 后**重新登录**，或 `newgrp docker`），可以不加 sudo。

脚本支持参数化安装，把变量写在 `bash install.sh` 之前即可（都会被写回 `.env`）：

```bash
./install.sh                                  # 就地安装到当前目录（默认，推荐）
./install.sh /opt/dir2chat                    # 指定安装目录（只拷运行所需文件）
DIR2CHAT_PORT=8091 ./install.sh               # 8899 被占用时换端口（自动写回 .env 并重建容器）
WATCH_DIR=/你真实的目录 ./install.sh          # 直接指定监听目录（自动写回 .env，覆盖默认值）
FORCE=1 ./install.sh                          # 目录已部署过时，覆盖程序文件但保留数据(config/ 与 .env)

# 可叠加：一次把端口和监听目录都定好
sudo DIR2CHAT_PORT=8091 WATCH_DIR=/你真实的目录 bash install.sh
```

脚本会自动完成：解析目录/端口/监听目录 → 部署文件 → 检查 Docker → 生成 `.env` → 校验监听目录 → 创建 `config/` → 拉取镜像 → 启动容器 → 等待健康检查。

> **Windows 用户**：在 WSL2 或 Git Bash 里跑 `sudo bash install.sh`；或 Docker Desktop 装好后直接手动 `docker compose up -d`（跳过脚本）。

### 方式二：手动 docker compose（不跑脚本）

把仓库里的 `docker-compose.yml` 和 `.env.example` 放到同一个目录，把 `.env.example` 改名为 `.env` 并填好 `WATCH_DIR`，然后：

```bash
sudo docker compose pull      # 拉取镜像（首次约 250MB）
sudo docker compose up -d     # 启动
```

或者不用 compose，一条 `docker run` 直接起：

```bash
sudo docker run -d --name dir2chat --restart unless-stopped \
  --network bridge -p 8899:8899 \
  -v "$PWD/config:/config" \
  -v /你真实的目录:/data:ro \
  -e DIR2CHAT_CONFIG_DIR=/config -e TZ=Asia/Shanghai \
  smi1ezz/dir2chat:26.10.17
```

```

### 安装目录结构（用 `./install.sh <目录>` 安装后）

脚本**只拷贝跑起来真正需要的文件**；文档、开发工具留在仓库目录，安装目录保持干净：

```

> 用默认的「就地安装」（`./install.sh` 不带目录）时，仓库目录本身就是安装目录，不存在拷贝这一步。

## 4. 配置监听目录（必须）

两种方式，任选其一。

**方式一（推荐）：安装时直接带变量**，脚本会自动写进 `.env`：

```bash
sudo WATCH_DIR=/你真实的目录 bash install.sh
```

**方式二：装完之后手动改 `.env`**：

```ini
WATCH_DIR=/你真实的目录
DIR2CHAT_PORT=8899
```

> **⚠ 改 `.env` 前先确认有 root 权限。** 用 `sudo bash install.sh` 装的话，`.env` 与 `config/` 都归 root 所有，普通用户编辑器会提示只读 / 无法保存 —— 请用 `sudo nano .env`（或 `sudo vi .env`）编辑，改完再 `sudo docker compose up -d`。

> **⚠ 一行一条，不要把两行写在同一行。** 常见错误（会导致两个配置项同时失效）：
>
> ```
> WATCH_DIR=/你真实的目录DIR2CHAT_PORT=8899
> ```
>
> `WATCH_DIR=...` 后面必须换行。安装脚本写 `.env` 时会自动保证「一行一条」，不会追加到上一行末尾。

这个目录会被**只读**挂进容器的 `/data`。dir2chat 会**递归**扫描其下的子目录——所以像 `share/2026-10-11/` 这样的日期子目录也能自动识别。

改完 `.env` 后让配置生效：

```bash
sudo docker compose up -d
```

> 提示：`.env` 里写的是**宿主机路径**；容器内部固定是 `/data`。配置规则时填 `/data`。

## 5. Web 界面配置（三步）

浏览器打开 `http://<机器IP>:8899`。

1. **通道** tab → 填**通道名称**（如「投资群」）→ 选类型 → 「新增通道」→ 填凭据 → 点「测试」确认连通
2. **规则** tab → 「新增规则」→ `watch_dir` 填 `/data`，`include` 填 `*.png` + `*.md` → **点击**下方通道标签绑定
3. 回到「概览」点「立即扫描」，看「记录」里有没有成功发出的条目

> 多个同类通道容易混淆？给每个通道起个自定义名称，规则绑定处和发送记录里都会显示这个名字。

### 5.1 企业微信群机器人 Webhook（最简单）

在企业微信客户端：**群设置 → 添加群机器人 → 获取 Webhook 地址**，把整条 URL 填进 `webhook_url`。

- 限制：图片 ≤2MB（dir2chat 会自动压缩）、文件 5B–20MB、file 消息**无法指定文件名**、20 条/分钟
- 仅企业内部群；只发不收

### 5.2 企业微信智能机器人（长连接，能力最强）

在「企业微信管理后台 → 智能机器人」创建，拿到 `bot_id` / `secret`。把机器人加入目标群后，从群会话回调里拿到 `chatid`（dir2chat 也会缓存最近收到的会话，可在「通道 → 健康/会话」里选）。

- 群聊：`chat_type` 填 `2`
- 能力：图片 ≤10MB、文件 ≤20MB 且**带文件名**、Markdown ≤20KB
- **没有 text 类型**——纯文本由 markdown 承载（这是官方限制，不是 bug）
- 速率：上传 30 次/分钟、消息 30 条/分钟/会话
- 同样只能进**企业内部群**

### 5.3 企业微信应用消息（可发给指定成员）

需要企业自建应用：`corpid` + `corpsecret` + `agentid`。

- 这是**唯一能指定发给某个成员**的通道（`touser`）
- 临时素材 3 天有效

### 5.4 QQ 官方机器人（OpenAPI v2）

在 QQ 开放平台创建机器人，拿到 `appId` + `clientSecret`。

- 群聊主动推送需**群主**在群设置里开启「机器人主动在群聊内发言」（2026-06-22 起全面开放）
- 群和私聊的上传端点独立，`file_info` 不通用
- 速率：已认证 60 次/分钟（bot 级）/ 未认证 30；单群 20 次/分钟

## 6. 定时开关（**每条规则独立控制**）

不想让它在任何时间都推送？在**每条规则内部**打开 **⏰ 定时开关**，各规则互不影响：

- **开启后**，只有在该规则的**时间窗口**内才会扫描并推送这条规则；**窗口外自动暂停**该规则（文件不会丢，回到窗口后继续推送）。
- **不同规则可设不同时段**：例如「行情图」规则只在 `09:00–15:00` 推送，「日报」规则全天推送。
- **手动「立即扫描」不受定时限制**——任何时候都能强制触发一次。
- 支持**多条时间窗口**，也支持**跨午夜**，例如 `22:00 – 06:00`。
- **时区**默认 `Asia/Shanghai`（依赖 `tzdata`；无时区数据则回退服务器本地时间）。
- 规则卡片实时显示相位：「✅ 当前在推送窗口内」或「⏸ 窗口外暂停」。
- 配置保存在 `config/config.json` 的 `rules[].schedule`，重新部署时保留。

> 说明：0.4.0 的「全局定时」在本版已移除，改为规则级——这样不同目录/不同内容可以用完全不同的推送节奏。

### 6.1 轮询间隔可调（全局 + 规则级）

- **全局**：「概览 → 扫描设置」里可改轮询间隔（秒，最小 5）、文件稳定时间、每轮最多处理文件数、扫描总开关，点「保存扫描设置」生效（存于 `scan.*`）。
- **规则级**：每条规则的「独立轮询间隔」填 `0` 或留空 = 跟随全局；填 ≥5 的整数则该规则单独按此间隔扫描（存于 `rules[].interval_seconds`）。
- 不同规则可用不同节奏，互不干扰。改小更及时，改大更省资源。

### 6.2 绑定通道只显示已启用的通道

规则卡片的通道绑定列表默认**只列出已启用的通道**；未启用的不再出现。若某个已绑定的通道随后被停用，它仍会保留显示（虚线灰显 + 「已停用」标签），方便你手动解绑，不会出现「看不见又解不掉」的死角。

### 6.3 配置备份 / 导入

「概览」页新增**配置备份**：

- **⬇ 备份配置**：导出全部配置（通道凭据、规则、定时、扫描参数）为一份 JSON。
- **⬆ 导入配置**：选择 JSON 文件**整体覆盖**当前配置（有二次确认）。
- 适合迁移到新机器、或备份后误删恢复。

### 6.4 时区与时间（自动同步 / 手动设置）

「概览」页新增**时区与时间**区块：

- **实时时钟**：按所选时区每秒跳动，旁边显示时区偏移徽标。
- **时区可调**：内置常用时区（默认 `Asia/Shanghai` = UTC+08:00 北京/重庆/中国香港），并自动补充 zoneinfo 里的其它地区。
- **自动同步**：选好时间服务器（如 `ntp.tencent.com`、`time.cloudflare.com`）后点「立即同步」；后台也会按 `time.auto_sync_hours`（默认 6 小时）周期自动对时。点「测试服务器」只查询、不改时间，会显示本机偏差与网络延迟。
- **自定义服务器**：在「自定义服务器」区填入地址点「添加」，即可加入下拉并可选中。  
  支持**域名 / IPv4 / IPv6 / 局域网主机名**，可带端口，例如 `192.168.1.1`、`ntp.local`、  
  `192.168.1.5:123`、`[fe80::1]:123`；误粘贴的 `ntp://`、`http://` 前缀会被自动剥掉。  
  已添加项以 chip 展示，点 chip 上的 `×` 可删除（删除正在使用的项会回落默认服务器）。
- **手动设置**：切到「手动设置」，选好日期时间后点「应用时间」（可先点「填入当前时间」）。

> 校时需要 `CAP_SYS_TIME` 权限，已在 `docker-compose.yml` 里加上 `cap_add: [SYS_TIME]`。  
> 若权限缺失，界面会明确提示原因与改法，不会静默失败。  
> 时间同步用内置的轻量 SNTP 客户端（UDP 123 标准报文），**不依赖** ntpd / chrony / systemd-timesyncd。

### 6.5 手机端适配

界面已适配手机浏览器：

- 顶栏运行状态默认收起，点 **📊** 图标展开/折叠（顶栏高度 237px → 77px）。
- 触摸目标加大：按钮 ≥40px、主要操作 ≥42px、单选与开关标签 ≥40px。
- 表单在窄屏改为单列全宽，输入框 42px 高、15px 字号（避免 iOS 聚焦自动放大）。
- 窄屏下标签栏可横向滑动且吸顶；表格横向滚动更顺滑，分页按钮更易点。
- 已适配全面屏底部安全区，并去掉了触屏上「粘住」的悬停样式。

## 7. 推送规则与行为

- **轮询扫描**：默认 60s 一次；文件需「稳定 5s 且大小两次扫描不变」才处理，避免发半截文件
- **幂等**：同一 `(规则, 通道, 路径, sha256)` 只发一次；内容变了才会重发。所以每天重写过的报告会重发，没动过的文件不会刷屏
- **图片压缩**：超过通道上限自动压（webhook 2MB / 智能机器人 10MB）
- **Markdown 退化**：超过 3800 字节自动变成文件消息；再超长会切片并带 `(i/n)` 标记
- **企业微信 webhook 的 file 消息无文件名**（官方限制）——若要在聊天里看出是哪份报告，可调低 Markdown 上限让它多发图片，或直接用智能机器人通道（文件带文件名）

### 7.1 扫描性能调优（三个可调参数）

> 适用：**监听目录会按天累积**的场景（例如每天新建一个 `2026-10-12/` 放当天报告）——文件总数会一路增长，下面三个参数用来保证「文件再多也不会漏推、也不会每分钟重复读盘」。
>
> 全部在 **Web 界面 → 扫描设置** 里可调，改完点「保存扫描设置」即刻生效，无需重启容器。（界面底层是 `PUT /api/config`；也可以直接编辑挂载目录下的 `config/config.json` 后重启容器。）

| 参数 | 默认 | 作用 | 怎么设置 |
|---|---|---|---|
| `max_files_per_round`<br>每轮最多推送文件数 | **500** | 单轮最多往队列里放多少个**待推送**文件，避免一次灌入过多任务压垮通道 | **已推送过的历史文件不占这个名额**，所以基本不需要调大。设得比你的**单日新增量**大即可——每天 30 个保持默认 500 就绰绰有余 |
| `digest_cache_max_entries`<br>内容哈希缓存条数 | **5000** | 记住每个文件的「大小 + 修改时间 + 哈希」，再扫到时三者都没变就**直接复用**、不再把文件读一遍重算 | 约 300 字节/条，5000 条才 ~2MB；按「日增量」估算能覆盖多少天（每天 30 个 → 约 166 天）。设 **0 = 关闭缓存**（回到每轮全量重算，仅建议排查问题时用） |
| `skip_dirs_idle_days`<br>目录冷却跳过（天） | **0（关闭）** | 子目录超过 N 天没有任何变动，就**整棵子树都不再进去扫描**，历史快照的 stat+哈希开销降到 0 | 适合「每天一个日期目录、旧目录永不改动」的场景，设 **2** 表示两天没动静的目录不再扫。<br>**⚠️ 副作用：被跳过的目录不再参与任何扫描**——里面的失败重试、以及「清空发送记录」后的补推都不会发生。需要重推时请先把它改回 0 |

> **重要**：这三个参数只影响**性能**，不影响推送的正确性。真正的去重始终由 `(规则, 通道, 路径, sha256)` 四元组决定；缓存没命中顶多是多算一次哈希，**不会**导致重复推送或漏推。

### 7.2 递归与过滤（recursive / include / exclude）

规则页里的这三个字段，决定「哪些文件会被看到」：

- **是否递归 `recursive`**
  - **是（默认）**：`watch_dir` 下**所有层级的子目录**都会进去扫。
  - **否**：只看 `watch_dir` **这一层**，完全不进入子目录。
  - ⚠️ 若你的文件都放在日期子目录里（如 `share/2026-10-12/xxx.png`），**必须保持「是」**；一旦关掉会变成「命中 0 文件」，因为根目录本身并不直接存放文件。

- **包含 `include`**：只推送命中的文件。大小写不敏感，支持通配符。
  - 例如 `*.png`、`*.md`、`report_*.pdf`
  - 懒人写法：裸写 `png` 会自动当作 `*.png`；留空等同于 `*` 全部。

- **排除 `exclude`**：命中则跳过，优先级高于 include。
  - **对目录名同样生效，且是整棵子树剪枝**：例如填 `test-verify`，则整个 `test-verify/` 目录（不管内部嵌多少层）都不会被扫描。
  - 常用来排除临时目录 / 噪声目录；以 `.` 开头的隐藏目录始终不扫。
  - 另外：`.tmp` / `.part` / `.crdownload` 结尾的文件永远跳过（避免抓到下载或写入中的半截文件），0 字节文件同样忽略。

## 8. 记录页

- **两个并列按钮**：「发送记录」与「事件日志」，点哪个显示哪个。
- 表格宽度固定，内容超长自动**省略号截断**，**鼠标悬停显示完整内容**；列较多时可**横向滚动**。
- **筛选**：时间（模糊匹配，如 `2026-10` 或 `17:2`）、通道、类型、级别（事件日志）；发送记录另有「只看失败/跳过」。
- **分页**：每页固定 **15 行**，超出只翻页、**纵向不滚动**；不足 15 行补空行，因此每页高度恒定不跳动。
- **空白处也能翻页**：表格下方留白点一下即翻到下一页（到末页后再点翻上一页）；点到表格/按钮本身不会误触发。
- **⬇ 导出**：把当前筛选结果导出为 CSV（带 BOM，Excel 打开中文不乱码）。

> 页面内容区**铺满整个窗口宽度**（不做居中收窄），因此在宽屏上任意位置都能滚动，不会出现两侧"死边距"。

## 9. 日常管理

> 下面命令默认都带 `sudo`。若当前用户已加入 `docker` 组，可以把 `sudo` 去掉。

```bash
# 状态
curl http://<IP>:8899/api/status
# 或看界面「概览」

# 备份配置（导出 JSON）
curl -OJ http://<IP>:8899/api/config/export

# 停止
sudo docker compose down

# 重启
sudo docker compose restart

# 看日志
sudo docker compose logs -f

# 升级到最新镜像
sudo docker compose pull && sudo docker compose up -d

# 改配置（sudo 装的 .env 归 root 所有，必须加 sudo 才能保存）
sudo nano .env

# 卸载
sudo docker compose down && rm -rf config .env
```

## 10. 从源码构建（可选）

正常情况下直接用 Docker Hub 上的官方镜像即可，**不需要构建**。只有这两种情况才需要自己构建：
① 你改了源码 / `Dockerfile` / `requirements.txt`；② 目标架构特殊、官方镜像跑不了。构建时需要联网拉基础镜像 `python:3.11-slim`。

```bash
# 在仓库目录里构建（打成与 compose 里相同的镜像名）+ 重建容器
sudo docker compose build
sudo docker compose up -d --force-recreate
```

> **⚠ 改完源码 / 依赖却不生效？多半是复用了旧的构建缓存。**
> Docker 逐层缓存，`requirements.txt` 没变时 `pip install` 那一层会直接复用，新代码就进不去镜像。

```bash
# 1) 忽略缓存、从头构建（最常用）
sudo docker compose build --no-cache
sudo docker compose up -d --force-recreate

# 2) 清理 BuildKit 构建缓存（-a 连未使用的一起清；-f 不交互确认）
sudo docker builder prune            # 交互确认后清理
sudo docker builder prune -af        # 直接全部清掉

# 3) 清理悬空镜像（构建残留的 <none> 旧层）
sudo docker image prune -f

# 4) 先看看各类占用多少，再决定清哪个
sudo docker system df

# 5) 彻底清干净（慎用：会删掉所有未使用的镜像 / 缓存 / 网络）
sudo docker system prune -af
```

> 清构建缓存只影响下次构建速度（需重新下载 / 安装依赖），**不会动到 `config/` 里的数据** —— 通道、规则、发送记录都在 `config/` 卷里。

## 11. 故障排查

| 现象                   | 处理                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------- |
| 端口被占用                | 改 `docker-compose.yml` 里 `8899:8899` 的左边端口，如 `9090:8899`                                                        |
| 目标架构与镜像不符 | 官方镜像已支持 amd64 / arm64；其它架构请用 `docker compose build` 从源码构建 |
| 扫描不到文件               | 检查 `.env` 的 `WATCH_DIR` 是否存在、容器是否挂上了 `/data`、规则的 `include` 通配是否正确                                               |
| 通道「测试」失败             | 看返回的错误码说明（界面会解释常见 errcode，如 45009 频率限制、93000 参数错误）                                                              |
| 规则绑定时看不到新通道          | 点规则页右上角「↻ 刷新通道」                                                                                                 |
| 镜像拉取慢 / 超时 | 给 Docker 配置镜像加速器（`daemon.json` 的 `registry-mirrors`）后重试 `docker compose pull` |
| 定时开关不生效              | 确认**该规则**的「定时开关」已启用且时间窗口非空；改用「立即扫描」可随时强制推送验证通道                                                                  |
| 改了轮询间隔没生效            | 概览页改完要点「保存扫描设置」；规则里设了「独立轮询间隔」会覆盖全局                                                                              |
| 规则里看不到某个通道           | 该通道未启用。先到「通道」页把它「启用」，或点规则页「↻ 刷新通道」                                                                              |
| 改了系统时间/同步失败          | 容器缺少 `CAP_SYS_TIME`。确认 `docker-compose.yml` 里有 `cap_add: [SYS_TIME]`，然后 `docker compose up -d --force-recreate` |
| 时间服务器连不上             | 容器 DNS 或出网受限。先点「测试服务器」看具体报错；可换 `ntp.aliyun.com` 或 `cn.pool.ntp.org` 再试                                          |
| 时区切换后时间没变            | 时区只改变「显示与判断基准」，不会改系统时钟。想让时钟也正确，需配好时间同步或手动设置时间                                                                   |
| 手机上顶栏太高              | 点顶栏 **📊** 图标可收起/展开运行状态                                                                                         |
| 翻页时旁边的空白不动           | 内容区由通栏滚动容器承载，点任意留白（含滚动条旁）都能翻页；若仍是旧样式请强制刷新（Ctrl/Cmd+Shift+R）清缓存                                                  |
| 内容太宽/太窄              | 顶栏、标签栏、内容区共用同一宽度变量（默认最大 1543px，居中）；窗口 ≤1600px 时自动取消上限                                                           |
| 自定义时间服务器添加失败         | 检查地址是否含非法字符、端口是否在 1–65535、长度是否超 255；界面会给出具体原因                                                                   |
| NTP 同步失败             | 先在「测试服务器」确认服务器是否可达；局域网服务器请确认 UDP 123 未被防火墙拦截                                                                    |
| 时间/记录显示时区不对          | 检查「概览」页的时区下拉是否选对；切换后记录时间会按新时区显示                                                                                 |
